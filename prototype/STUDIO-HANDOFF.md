# 交接说明：像素小屋原型 → 继续开发

给接手的开发者 / 设计工作室 / AI 建站工具。请先读这一页，再读上一层目录的 `pixel-room-spec.md`（完整设计稿）。

## 现在的状态

- 这是设计稿第 15 节里的 **M1 可点击原型**，已经能完整跑通：房间、角色眨眼、10 个可点物件、全部面板、照片上传 → 像素拍立得 → 放进房间 → 点击显影
- 纯 HTML / CSS / JavaScript（ES Modules），**没有依赖、没有构建步骤**
- 本地运行：在 `prototype` 目录执行 `python tools/serve.py`，打开 http://127.0.0.1:5173
- 文件结构、改内容、换美术、嵌入方式见 `README.md`

## 必须保持的规则

1. **不要用代码画美术。** 房间、角色、物件都来自 `assets/` 里的 PNG。不能用 div / CSS 形状 / SVG 去画。缺图就放占位框。
2. **画面都画在一张逻辑分辨率的画布上**（现在是 240×135，`js/room.js`），再整数倍放大、`image-rendering: pixelated`。坐标和位移一律是整数逻辑像素。
3. **坐标只写在 `data/scene.json`，文字只写在 `data/content.json`。** 不要把内容写死在 JS 里。
4. **像素字体只用 12 的整数倍字号**（12 / 24 / 36），否则会糊。
5. **颜色**：房间和 UI 只用设计稿第 3.3 节的主调色板；照片摆件额外允许 8 个「照片补充色」。
6. **无障碍不能丢**：每个物件都是 `<button>`，有 `aria-label`；面板要锁焦点，Esc 能关，关闭后焦点回到原物件；支持 `prefers-reduced-motion`。

## 已知问题

- 照片只存在当前浏览器（IndexedDB），没有后台
- 物件画在背景图里，不能单独动；悬停只有四角框
- 手机竖屏上下留白较多
- 背景音乐是浏览器实时合成的占位
